# Multi-Database Provider Support

This project supports **multiple database providers** with automatic configuration switching between SQL Server and PostgreSQL.

## Overview

The application can dynamically switch between database providers based on configuration. Each provider has its own:
- Connection string
- Migration history table
- Migrations folder with provider-specific schema

## Supported Providers

| Provider | Config Value | Connection String Key | Migrations Folder |
|----------|-------------|----------------------|-------------------|
| SQL Server | `sqlserver` (default) | `default` | `Infrastructure/Data/Migrations/SqlServer/` |
| PostgreSQL | `postgresql` or `postgres` | `default_postgres` | `Infrastructure/Data/Migrations/PostgreSql/` |

## Configuration

### Setting the Database Provider

In [appsettings.json](WebApi/appsettings.json) or [appsettings.Development.json](WebApi/appsettings.Development.json):

```json
{
  "DatabaseProvider": "postgresql",
  "ConnectionStrings": {
    "default": "Server=localhost;Database=default_db;user id=YourUser;password=YourPassword;Trusted_Connection=True;MultipleActiveResultSets=true;TrustServerCertificate=True",
    "default_postgres": "Host=localhost;Port=5432;Database=default_db;Username=postgres;Password=YourPassword",
    "redis": "127.0.0.1"
  }
}
```

### Provider Values

- **SQL Server:** `"DatabaseProvider": "sqlserver"` (or omit - it's the default)
- **PostgreSQL:** `"DatabaseProvider": "postgresql"` or `"postgres"`

## Connection String Formats

### SQL Server
```
Server=localhost;Database=default_db;user id=YourUser;password=YourPassword;Trusted_Connection=True;MultipleActiveResultSets=true;TrustServerCertificate=True
```

### PostgreSQL
```
Host=localhost;Port=5432;Database=default_db;Username=postgres;Password=YourPassword
```

**Note:** PostgreSQL uses different parameter names:
- `Host` instead of `Server`
- `Username` instead of `User ID`
- No `Trusted_Connection` (SQL Server specific)

## Naming Conventions

### SQL Server
- Uses **PascalCase** for table and column names
- Example: `Users`, `UserName`, `CreatedDate`

### PostgreSQL
- Uses **snake_case** for table and column names (via [EFCore.NamingConventions](https://github.com/efcore/EFCore.NamingConventions))
- Example: `users`, `user_name`, `created_date`

Your C# entities always use PascalCase - EF Core handles the mapping automatically.

**Example Entity:**
```csharp
public class UserInfo : EntityBase
{
    public int Id { get; set; }
    public string? UserName { get; set; }  // SQL Server: UserName, PostgreSQL: user_name
    public string? Email { get; set; }     // SQL Server: Email, PostgreSQL: email
}
```

**Generated SQL:**

SQL Server:
```sql
CREATE TABLE Users (
    Id int NOT NULL IDENTITY,
    UserName nvarchar(max),
    Email nvarchar(max),
    CreatedDate datetime2,
    CONSTRAINT PK_Users PRIMARY KEY (Id)
);
```

PostgreSQL:
```sql
CREATE TABLE users (
    id integer GENERATED BY DEFAULT AS IDENTITY,
    user_name text,
    email text,
    created_date timestamp with time zone,
    CONSTRAINT pk_users PRIMARY KEY (id)
);
```

## Migrations

### Separate Migration Folders

Migrations are stored in provider-specific folders:
- **SQL Server:** `Infrastructure/Data/Migrations/SqlServer/`
- **PostgreSQL:** `Infrastructure/Data/Migrations/PostgreSql/`

Each provider has its own migration history table:
- **SQL Server:** `__EFMigrationsHistory_SqlServer`
- **PostgreSQL:** `__ef_migrations_history_postgre_sql`

### Creating Migrations

#### For SQL Server
```powershell
# Set DatabaseProvider to "sqlserver" in appsettings.json first
dotnet ef migrations add MigrationName --project Infrastructure --startup-project WebApi --output-dir Data/Migrations/SqlServer
```

#### For PostgreSQL
```powershell
# Set DatabaseProvider to "postgresql" in appsettings.json first
dotnet ef migrations add MigrationName --project Infrastructure --startup-project WebApi --output-dir Data/Migrations/PostgreSql
```

### Applying Migrations

```powershell
# Applies migrations for the currently configured provider
dotnet ef database update --project Infrastructure --startup-project WebApi
```

### Listing Migrations

```powershell
dotnet ef migrations list --project Infrastructure --startup-project WebApi
```

## How It Works

### Provider-Specific Migration Assembly

The project uses a custom `IMigrationsAssembly` implementation to filter migrations by namespace:

- [ProviderMigrationsAssembly.cs](Infrastructure/Data/Migrations/ProviderMigrationsAssembly.cs) - Base class that filters migrations
- `PostgreSqlMigrationsAssembly` - Only loads migrations from `Infrastructure.Data.Migrations.PostgreSql`
- `SqlServerMigrationsAssembly` - Only loads migrations from `Infrastructure.Data.Migrations.SqlServer`

### Configuration in Program.cs

```csharp
builder.Services.AddDbContext<AppDbContext>(options =>
{
    switch (dbProvider.ToLower())
    {
        case "postgres":
        case "postgresql":
            options.UseNpgsql(connectionString, x => x
                .MigrationsAssembly("Infrastructure")
                .MigrationsHistoryTable("__ef_migrations_history_postgre_sql"))
                .UseSnakeCaseNamingConvention();
            options.ReplaceService<IMigrationsAssembly, PostgreSqlMigrationsAssembly>();
            break;
        case "sqlserver":
        default:
            options.UseSqlServer(connectionString, x => x
                .MigrationsAssembly("Infrastructure")
                .MigrationsHistoryTable("__EFMigrationsHistory_SqlServer"));
            options.ReplaceService<IMigrationsAssembly, SqlServerMigrationsAssembly>();
            break;
    }
});
```

## Health Checks

Health checks are automatically configured for the active database provider:

- **SQL Server:** `AddSqlServer()` health check
- **PostgreSQL:** `AddNpgSql()` health check

```http
GET /health
```

Response shows the active database check:
```json
{
  "status": "Healthy",
  "checks": [
    {
      "name": "postgresql",
      "status": "Healthy",
      "duration": 23.5
    }
  ]
}
```

## Switching Providers

### Development Workflow

1. Update `DatabaseProvider` in `appsettings.Development.json`
2. Ensure the correct connection string is configured
3. Run migrations: `dotnet ef database update --project Infrastructure --startup-project WebApi`
4. Start the application

### Production Deployment

1. Set environment variable or configuration:
   ```bash
   DatabaseProvider=postgresql
   ConnectionStrings__default_postgres=Host=prod-server;Port=5432;Database=myapp;Username=app;Password=secret
   ```
2. Deploy application
3. Migrations are applied automatically on startup (if enabled) or via CI/CD

## Adding a New Provider

To add support for another database (e.g., MySQL, SQLite):

1. **Install the EF Core provider package:**
   ```bash
   dotnet add package Pomelo.EntityFrameworkCore.MySql
   ```

2. **Create migrations folder:**
   ```
   Infrastructure/Data/Migrations/MySql/
   ```

3. **Add migration assembly class** in `ProviderMigrationsAssembly.cs`:
   ```csharp
   public class MySqlMigrationsAssembly : ProviderMigrationsAssembly
   {
       protected override string MigrationsNamespace => "Infrastructure.Data.Migrations.MySql";
       // ... constructor
   }
   ```

4. **Add configuration in Program.cs:**
   ```csharp
   case "mysql":
       options.UseMySql(connectionString, ServerVersion.AutoDetect(connectionString), x => x
           .MigrationsAssembly("Infrastructure")
           .MigrationsHistoryTable("__EFMigrationsHistory_MySql"));
       options.ReplaceService<IMigrationsAssembly, MySqlMigrationsAssembly>();
       break;
   ```

5. **Add health check:**
   ```csharp
   case "mysql":
       healthChecks.AddMySql(connectionString!, name: "mysql", tags: new[] { "db", "mysql" });
       break;
   ```

6. **Create initial migration:**
   ```bash
   dotnet ef migrations add Initial --project Infrastructure --startup-project WebApi --output-dir Data/Migrations/MySql
   ```

## Troubleshooting

### "type 'nvarchar' does not exist" (PostgreSQL)

**Problem:** Applying SQL Server migrations to PostgreSQL

**Solution:** Ensure you're using the correct migrations folder. Check that:
1. `DatabaseProvider` is set to `postgresql`
2. PostgreSQL-specific migrations exist in `Data/Migrations/PostgreSql/`
3. The custom `IMigrationsAssembly` is registered

### "Couldn't set trusted_connection"

**Problem:** PostgreSQL connection string has SQL Server parameters

**Solution:** Use PostgreSQL connection string format:
```
Host=localhost;Port=5432;Database=mydb;Username=user;Password=pass
```

Not:
```
Server=localhost;Database=mydb;User ID=user;Trusted_Connection=True
```

### Migrations Not Found

**Problem:** `dotnet ef migrations list` shows no migrations

**Solution:** Verify migrations exist in the correct namespace:
- SQL Server: `Infrastructure.Data.Migrations.SqlServer`
- PostgreSQL: `Infrastructure.Data.Migrations.PostgreSql`

Check the namespace in your migration files matches the folder structure.

### Wrong Tables Being Created

**Problem:** Tables have wrong naming convention

**Solution:** Ensure `UseSnakeCaseNamingConvention()` is called for PostgreSQL:
```csharp
options.UseNpgsql(connectionString, ...)
    .UseSnakeCaseNamingConvention();  // Must be chained after UseNpgsql
```

## Summary

- **Dynamic Provider Switching** - Change database with configuration only
- **Separate Migrations** - Each provider has isolated migrations
- **Automatic Naming** - Snake case for PostgreSQL, PascalCase for SQL Server
- **Health Checks** - Provider-aware health monitoring
- **Extensible** - Easy to add new database providers
